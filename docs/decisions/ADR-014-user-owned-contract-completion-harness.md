# ADR-014: 사용자 소유 계약과 독립 평가 기반 완료 하네스

## Status

Accepted. ADR-013의 계약 권위·렌더링·완료 판정 방향을 대체한다.
설계 승인과 구현 완료는 별개이며, 실제 지원 범위는 코드와 검증 증거를 따른다.

## Context

OMS가 템플릿 문법 해석, 노트 작성, 계약 검사까지 소유하면 사용자 지침과
특정 도구의 실행 방식이 결합된다. 원본 변경이 볼트 전체를 막거나, 형식이
맞다는 이유로 내용도 적절하다고 보고하는 문제가 생긴다.

사용자는 이미 속성·허용값·폴더·섹션의 의도를 표현한다. OMS는 그 의도를
다시 정의하는 시스템이 아니라, 에이전트가 이해한 규칙을 사용자가 승인하고
실제 작성 결과에 적용하는 범용 하네스여야 한다.

## Decision

### 책임과 권위

- 사용자는 볼트 정책과 의미의 최종 권위를 가진다.
- 작성 에이전트는 지침을 이해하고 계약을 제안하며 노트를 작성·수정한다.
- OMS는 볼트·작성 위치·승인 계약을 안내하고 실제 저장된 결과를 검사한다.
- 호스트의 별도 reviewer는 승인된 의미 기준으로 평가한다.
- OMS는 기계 검사와 의미 평가를 구분하고 해당 작업의 완료 여부를 판정한다.

특정 사용자, 볼트 경로, 필드명, 헤딩 이름의 의미를 제품에 하드코딩하지 않는다.
Obsidian 타입은 읽기 전용 관측 자료이며, 충돌 진단이 OMS 승인 계약을
자동으로 교체하지 않는다.

### 빈 기본 템플릿과 추가 전용 합성

기본 템플릿은 처음에는 비어 있다. 사용자가 추가한 공통 속성·헤딩은 항상
적용하고, 개별 템플릿은 이를 추가·강화할 수 있지만 제거하거나 약화하지 않는다.
개별 템플릿이 없는 노트도 정상적인 관리 대상이다. 미관리 속성은 보존하고
검사에서 제외한다. 헤딩 순서는 기본 자유이며 명시적으로 강화할 수 있다.

에이전트가 원본 템플릿 문법을 순수 Markdown과 명시적 계약으로 해석한다.
OMS는 Templater 실행기나 자체 템플릿 언어를 소유하지 않는다. 원본 연결과
승인 snapshot은 보존하며, 변경된 원본·편집 중인 템플릿은 갱신 필요 상태로
알린다. 마지막 승인 계약으로 검사할 수 있는 동안 무관한 노트나 검색을 막지 않는다.

### 설정 인터뷰와 일반 질문

별도 `interview` 스킬은 초기 설정과 설정·계약의 생성·추가·변경·업데이트를
위한 절차다. 기존 지침과 의도를 먼저 읽고 필요한 결정을 한 번에 하나씩
확인하며, 최종 변경 내용을 보여주고 승인받는다.

작성 중 모르는 값이나 잘못된 결과는 일반 질문·수정·재검증으로 처리한다.
그 답변만으로 계약을 바꾸거나 인터뷰 스킬을 자동 실행하지 않는다.
[Gajae Code의 deep-interview](https://github.com/Yeachan-Heo/gajae-code/blob/main/packages/coding-agent/src/defaults/gjc/skills/deep-interview/SKILL.md)의
상호작용 원칙을 참고하되 GJC 런타임을 OMS의 필수 의존으로 만들지 않는다.

### 의미 평가와 완료

[Ouroboros](https://github.com/Q00/ouroboros)의 명시적 계약, 작성·평가 분리,
단계적 검증과 근거 기반 완료 판정을 참고한다. 전체 실행 엔진이나 모델
공급자 체계를 이식하지 않는다.

의미 기준은 기존 의도·지침에서 근거를 찾아 기계 규칙과 함께 승인받는다.
기계적 통과와 필요한 의미 기준 충족을 모두 확인해야 작업 완료다.
검사한 노트·계약·근거 snapshot이 달라지면 과거 결과를 재사용하지 않는다.
미실행 reviewer, 기준 누락, 자료 부족, 실행 실패는 통과가 아니다.
에이전트가 자료를 보충하고 재평가하되 해결되지 않으면 사용자에게 확인한다.

독립성의 기준은 작성자와 별도 평가 역할·대화, 수정 금지 지침, 평가 입력의
전후 변경 검사다. 도구 권한을 강제로 제한하는 sandbox는 선택적 강화다.
호스트가 보고한 실행 사실과 OMS가 직접 검사한 바이트를 구별하고, 선언된
설정을 읽었다는 이유로 실제 격리나 의미적 진실성을 보증하지 않는다.
노트 안의 지시문은 평가 기준이 아니라 검사 대상 데이터다.

### 검색과 수정

저장됨, 검사 통과, 작업 완료는 다르다. 미완료·위반 노트도 검색 가능하다.
기존 임베딩·축 검색과 ADR-007의 명시적 실패 원칙을 유지하며 검색이 검사,
인터뷰, 수정을 암묵적으로 실행하지 않는다.

자동수정은 기본 꺼짐이다. 사용자가 허용한 작성 후·명시적 정비 범위에서
에이전트가 수행하며, OMS 검증 호출 자체는 노트를 수정하지 않는다.
알 수 없는 값을 만들거나 계약을 약화해 통과시키지 않는다.

## Alternatives Considered

1. **기존 OMS renderer/writer에 judge만 추가:** 변경량은 작지만 작성·검사
   책임의 결합을 유지하므로 기각한다.
2. **OMS가 모델 API·인증·reviewer daemon까지 소유:** 호출 관측은 쉬워지지만
   호스트에 이미 있는 실행 기능을 중복하고 불필요한 책임을 추가하므로 기각한다.
3. **모든 호스트에 강제 쓰기 권한 차단 요구:** 별도 평가와 보안 격리를
   혼동하고 지원 가능한 호스트를 배제하므로 기본 요건으로 채택하지 않는다.

## Consequences

공개 작성·렌더링 경로를 정리하는 breaking 전환이다. 구버전 계약을 몰래
변환하거나 호환 reader로 의미 차이를 숨기지 않고 승인된 설정 재구성을 사용한다.
CLI·MCP·스킬·호스트 안내·테스트를 함께 갱신해야 한다.

평가 계약은 재현 가능한 입력과 판단 근거를 제공하지만, 악의적인 호스트의
주장이나 모델의 오판을 암호학적으로 방지하는 장치는 아니다. 이 한계를
완료 receipt와 사용자 안내에서 정직하게 표현한다.
