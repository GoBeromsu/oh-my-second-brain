# Architecture

Oh My Second Brain is an Obsidian-first vault integration. It keeps the vault as plain Markdown the user owns, and it separates that meaning from generated runtime data. Obsidian remains usable when OMS is absent. OMS does not become the note store, and one example does not become a required rule.

These pages record the approved architecture. They are not a host-smoke result and not a product-gate pass. The text figure below is a repository sketch. It is not the G002 Excalidraw artifact, which has to be drawn in the bound vault and checked by save, reload, and render.

## Authorities and derived state

```text
oms setup (interactive, user only)
        │  interviews folders, property pool, and templates together
        ▼
sealed contract            ~/.oms/vaults/<vault-id>/   outside the vault
        │
        ├── .oms/settings.json      the only OMS file inside the vault
        ├── templateFolder/*.md     the user's own templates, recorded by path and hash
        └── .obsidian/types.json    read-only observation, not the contract
```

The sealed contract is the only structural authority. It holds two axes: folders (meaning and search exclusion) and the property pool (meaning, Obsidian type, required flag, and allowed, fixed, pattern, or range rules). An axis the user did not seal stays open. OMS does not hardcode property names, folder names, personas, or the meaning of a heading, and it has no Inbox fallback.

The contract is stored per machine outside the vault, so an agent working inside the vault cannot read or edit it. `.oms/settings.json` carries `version`, `vaultId`, `templateFolder`, `embedding`, and `agentRepair`; unknown keys, including the former `templateRoots`, are refused. Any other entry under `.oms/` is ignored and reported by `oms doctor contract` as an unexpected control file.

A template stays the user's own Markdown file; OMS never rewrites, copies, snapshots, or applies it, and a new seal (manifest version 3) stores no templates. Generations sealed before manifest version 3 stored templates too; they still load, and `oms setup status` and `oms doctor contract` report their template constraints as `legacy-template-constraints-ignored` with a count, never enforcing them. The next reseal writes a version 3 head. OMS does not parse or execute Templater, JavaScript, or a private token language.

`.obsidian/types.json` is a read-only observation. OMS does not write the file and it never overrides the seal.

The vault contract is recorded in ADR-007, which replaces the former ADR-013 through ADR-016. [ACKNOWLEDGMENTS](../ACKNOWLEDGMENTS.md) records the debt to Ouroboros for an explicit contract and a split between writing and evaluation, and to Gajae Code's deep-interview for one confirmed question at a time. Neither credit is a code port or a measured research claim.

## One judge for every write

The agent writes the whole note. One judge decides every write against the seal, in a fixed order: base path rules (control paths, unsafe paths, paths outside the vault, YAML syntax), then the seal's readability, then folders, then properties. Templates are never judged: before the judge, the selected template in `templateFolder` scaffolds a new note, and the scaffolded note is judged like any other.

- MCP `write {path, content, template?, ifMatch?, check?}` judges the note and saves it atomically only when it is allowed. Unknown or missing input keys are refused before any judgement.
- In Claude Code, native Write, Edit, MultiEdit, and NotebookEdit inside the configured vault reach the same judge through the guard hook, which runs `oms hook pre`. A safety refusal denies the tool call; any other finding allows it and returns the warnings to Claude as `systemMessage` and `additionalContext`. When the judge cannot run, the call is allowed with a warning and the transport failure is recorded for `oms doctor contract`.
- The guard also denies reads and writes under `~/.oms/`, and Grep or Glob patterns that name it.
- Codex and Hermes have no write hook; their notes are judged only when written through MCP `write`.

Only safety refuses a write: control paths, unsafe paths, paths outside the vault, unsupported input, and a tampered contract. Overwriting an existing note also needs its current revision as `ifMatch`; a missing one returns `WRITE_IF_MATCH_REQUIRED` and a stale one `WRITE_TARGET_CHANGED`, and neither writes anything. A denial leaves the file unchanged and lists only those `{field, kind}` refusals and one guidance command, never a rule value, a store path, or the contract body. Every other finding is a warning that rides on the allowed write. Templates generate, axes judge: a template only seeds a new note, and the sealed axes (folders and properties) decide what a finding is worth. A write finding lands in one of three tiers. Safety refuses. A value the contract reads the same way in another spelling (a type, an allowed value's case, spacing or Unicode form, a missing value the contract fixes) is fixed losslessly, and the original is kept in the gap ledger as `fixed`. Everything else, an unknown key or a value outside its rule, is saved as written and recorded as `kept`. Only frontmatter that does not parse is kept as a draft: through MCP `write` or `oms write`, the response carries `status: "drafted"` with a `draftRef`. The guard hook never rewrites a tool call, so a fix it would make stays a warning. A vault with no seal on this machine is not judged; its writes carry a `contract-open` warning. A tampered vault id (a `.oms/settings.json` id that differs from this machine's index) refuses writes as `contract-tampered`. A missing or broken store, or a missing or invalid `.oms/settings.json`, lets writes through with a `contract-unreadable` warning suggesting `oms interview`.

The write pipeline binds conformance and template selection to a raw-source witness from the same inventory read. For new notes and explicitly named templates, `atomicWriteNote` revalidates that witness after staging and before the final target drift check; a failed hard-link publication revalidates again before the rename fallback. A mismatch returns `WRITE_TEMPLATE_SOURCE_CHANGED` with `retryable: true`, cleans the temporary file and skips the receipt, gap ledger and index update. The draft branch validates before creating its draft. The source witness is an optimistic observation of the configured template folder, discovered paths, exact-byte digests and scan diagnostics. It neither locks external editors nor creates a coherent multi-file snapshot; edits after a source's final read may still race publication. Target digest checks and no-clobber hard-link creation remain in place, with the existing check-to-rename window on overwrites and unsupported-hard-link filesystems.


Structural results do not evaluate the note's semantic quality. An allowed write is not a completion verdict. OMS has no completion operation and no reviewer handshake; deciding whether a note is worth keeping and repairing it belongs to the user and the agent. Note text is untrusted data, not new instructions. OMS adds no model provider, reviewer daemon, or repair workflow. The engine store, graph cache, and node index live outside the vault and are rebuildable. See [conventions](./conventions.md).

## Diagnosis and search

`oms setup status` reports the seal's posture and the number of legacy template constraints it ignores (`legacyTemplates`). `oms doctor contract` diagnoses the seal, stale locks, orphaned generations, unexpected control files, and hook transport failures, and exits 1 when unhealthy. `--fix` only re-indexes a moved or unindexed vault, or rebuilds an unreadable index; every other broken seal is recovered by running `oms interview` again. `oms doctor audit` judges existing notes and reports `{path, field, kind}` entries without rewriting them.

Search is independent of the contract. Lexical, vector, HyDE, and typed-axis queries include notes that would fail it, and a missing or damaged contract does not stop search. Sealed template sources and folders marked for search exclusion stay out of ordinary note results. Vector, HyDE, and rerank requests fail loudly when their provider and model pair is missing or unusable. Those failures are not replaced with an empty success or another backend. That is the ADR-005 boundary. Search does not write notes and does not repair anything.

Explicit `observed.field` filtering and `observed.discover` reuse `AxisObservationStore`, separate from declared `axes.field` semantics. The observed EAV snapshot is reconciled from the exact parsed current-note bytes captured for native FTS, and bound candidate paths are intersected in SQLite before `candidateLimit`. Scalar and list fields share the existing membership/range operators; incomparable members of mixed observed lists do not abort a query. Declared typed-axis behavior is unchanged. Observation is not a declaration, and no ranking or axis selection is inferred. Observed value facets include a transport-safe `selection: {exact: {valueType, value}}` predicate that binds the EAV value type and canonical normalized value directly. With unchanged sources, query, collection and predicates, applying it while preserving same-key conditions reproduces the facet's full-scope count and note set; replacing an existing predicate deliberately changes scope. The selector is a value predicate, not a scope token. Declared and legacy comparison coercions remain unchanged. Exact date selection accepts only canonical ISO strings emitted by facets, so invalid dates are not silently rolled forward.

Observed discovery returns keys or values for one key, distinct-note counts, and a cursor tied to the byte snapshot and filters. It considers the full native lexical match set before hit `limit`, `candidateLimit`, reranking, or score thresholds; metadata-only requests use the filtered current-note set. Canonical strings remain trimmed and lowercased. Entries over 512 UTF-8 bytes are omitted with an explicit `omittedCount`; `totalCount` includes them. Pages contain at most 100 entries and 32 KiB of serialized discovery JSON including the cursor, so the item limit is an upper bound. Remaining exact values continue through the cursor, which survives a new session with the same byte snapshot and rejects changed sources. `limit: 0` returns discovery without note hits. When discovery is requested with zero note hits, the ordinary `facets` array is empty so unbounded legacy facet values cannot overwhelm the bounded discovery page; ordinary non-observed responses are unchanged. Ordinary query payloads do not gain this metadata.

Canonical EAV rows are populated only on an explicit observed request and otherwise remain the last reconciled snapshot. Ordinary refresh prunes only obsolete binary backing rows; the next observed request authoritatively removes deleted/excluded canonical rows and updates the complete byte signature before exposing metadata selection or discovery. This preserves incremental reuse of unchanged EAV rows across renames and deletions without weakening direct-mutation invalidation. The same session-owned axis store also backs original compact lexical projections that exceed their object-cache budget. Its combined 64 MiB SQLite-page memory budget spills the same repository to session-private temporary storage outside the vault; no additional persistent index is introduced. Spill copies pages without a full JavaScript database buffer, retains every candidate and cursor, and is removed on shutdown. A failed spill rejects the whole request with no partial result, drains active source readers, and releases the failed backing store so a later request can recapture it. Other failures during observed preparation, including a stale discovery cursor, also release the shared EAV/backing store; the next query may reread unchanged overflow note bodies whose compact projections were not retained in RAM. This bounds retained database pages, not transient peak process memory while parsing/reconciling a dense note set. Malformed and unsupported metadata is reported through bounded diagnostic counts; lexical notes remain eligible without those field predicates. This initial observed path supports lexical and metadata-only queries, not vector/HyDE/expansion. Discovery uses one `collectionPath` scope rather than the multi-collection aggregation wrapper.


Queries against persisted vector/store-only snapshots require source evidence from an explicit index synchronization. The engine records each note's raw-byte digest, chunker settings, and filesystem identity (canonical vault/path, device, inode, size, nanosecond modification and change times) after verifying the indexed chunk set. Chunk mutations invalidate that note's evidence in the same SQLite transaction. Empty notes are covered too, so partial indexing cannot masquerade as a complete vault. Legacy stores without evidence remain readable for diagnosis; persisted snapshot queries report `INDEX_SOURCE_UNVERIFIED` until explicitly synchronized. Pure lexical search can instead establish this evidence in its detached live corpus without changing the persistent store.

An unchanged source check enumerates and stats eligible notes without reading their bodies when filesystem metadata is usable. Missing nanosecond fields, zero identities, and conservatively detected coarse timestamps force byte validation on both checks. Bytes are read from an open handle whose identity is checked against the captured pathname identity; returned previews must also match the indexed raw-byte digest. A changed stat witness is not itself proof of changed bytes: a byte-identical touch is accepted after hashing that note. Known changes or missing coverage in a persisted snapshot return no hits, `indexDrift: true`, and explicit synchronization guidance. Pure lexical queries refresh a detached native SQLite FTS corpus before retrieval: new and changed notes are captured with the canonical chunker, and deleted, renamed, or newly excluded paths are removed. Legacy evidence is rebuilt in that detached corpus only. Captured candidate lists retain their own text while another request refreshes the cache. A note changed during retrieval or preview validation still produces an explicit retry rather than mixed-revision matches, snippets, or exact-looking partial totals. Search never updates the persistent index or vault files. A validated detached lexical result, including `indexDrift: false`, certifies that read only; it does not certify synchronization of the untouched persistent/vector index. Stat witnesses are filesystem change detection, not cryptographic proof against adversarial metadata manipulation or filesystems that cannot distinguish edits. They do not certify vector completeness after a lexical-only synchronization.

MCP and HTTP retain one live lexical session per server and release it on shutdown. Stdio MCP installs its graceful EOF and termination-signal handler even when maintenance is disabled, so a completed read-only query releases spilled disk scratch on ordinary client closure. An unfinished query that outlasts a client's force-kill grace period, or another uncatchable process termination, can still leave an orphan directory; this does not add query cancellation or automatic orphan collection. Model/reranker adapters stay request-owned so changed model selections are observed without restarting the server; plain lexical calls do not load a model. SQLite pages above the 128 MiB in-memory budget spill to a disposable directory outside the vault; this bounds retained SQLite memory, not peak process memory while capturing a large database or note. Facets reuse the existing node projection over compact captured frontmatter, link targets, and body previews; raw note bodies and unused lexical terms are not retained for facets. This parsed-source object cache has a separate 64 MiB representation-size budget. Retained previews, link targets, keys, and scalar strings own copied UTF-16 storage rather than slices of the full note. Excess projections are serialized with `node:v8` into versioned binary rows in the existing private axis store, looked up by canonical note path and captured content SHA. They preserve original Dates, cycles, key casing, array/scalar shape, undefined values and UTF-16 strings rather than reconstructing from canonical EAV values. This Date preservation applies to original binary projections; observed EAV reconciliation intentionally converts Dates through `toAxisScalars` to ISO strings, then applies ordinary EAV string canonicalization. Unchanged bytes can reuse these rows on object-cache misses; missing, incompatible or damaged rows trigger byte recapture, never omission. Deserialized documents remain request-local and do not expand the object-cache budget. The full captured document set and node projections can still be transiently large; these budgets do not bound peak RSS. A failed spill releases oversized memory state before returning an error. DB/WAL generations guard bootstrap until the session has captured every admitted source with its canonical chunker. After complete capture, a stable canonical vault/device/inode identity lets the private corpus survive persistent writes, vector synchronization, rebuilds, removal, replacement, or schema changes without reseeding. Every query still scans the complete current source inventory and refreshes changed, missing, incompatible, or newly eligible evidence; removed/excluded paths also remove backing rows. Failed or incomplete captures, unknown root identity, or a replaced vault return to generation-checked bootstrap. The private corpus has its own source evidence and native schema; its freshness says nothing about persistent/vector synchronization or health. CLI search owns a transient session, so separate CLI invocations do not share a warm cache. Refresh always covers the complete admitted corpus before collection filtering and candidate limits, preserving native FTS ranking, totals, and pagination. Explicit vector, HyDE, and expansion requests keep their existing provider requirements and are not redirected to lexical search.

Full and collection-scoped synchronization reconcile deleted and newly excluded entries only within their scanned scope. A `files` slice updates only its selected notes, preserving the write pipeline's one-note keyword maintenance and unrelated source evidence. Read or directory failures are explicit failures rather than a successful partial scan.
The node cache (version 5) retains the authoritative byte-based source signature and adds a filesystem metadata witness over the complete included note paths, device/inode identity, size, nanosecond modification/change times, and metadata/exclusion digests. An unchanged warm cache is validated without reading ordinary note bodies; changed metadata falls back to the full byte hash, so a byte-identical touch is reusable and changed content remains an explicit stale-cache error. Missing or older caches are misses before any source-signature scan. Queries and graph exploration never write or refresh caches. `oms doctor build-graph` captures the witness before deriving edges, nodes, and the byte signature from one included document/byte set, then rereads the projection and witness before publishing either cache; a concurrent change fails the build without replacing either cache. Note parsing uses at most 32 concurrent file handles so large vaults do not exhaust the process descriptor limit. Captured bytes are read through file handles whose identity and size are checked against the initial scan and rechecked after reading; a temporary parent-directory replacement cannot attest bytes from a different inode. Missing or zero identity fields and missing/coarse timestamps never authorize metadata-only reuse: builds and reads fall back to exact bytes and persist no witness. This is filesystem change detection, not a cryptographic freshness guarantee on filesystems that conceal or coarsen identity/timestamp changes. Cache builders that supply no verified witness continue to require byte validation.

`status` reports observation. `doctor` diagnoses the contract and indexes. Its index repairs are explicit managed-state repairs after verified-target admission. Note backfill is not a repair. Target precedence and admission are in [verified targets](./verified-target.md).

After the live lexical corpus spills to disk, changed documents enter a bounded queue of owned V8-serialized canonical chunks and source evidence. At most 32 records and 1,024 chunks wait between reads; whole backing-buffer allocations plus a 512-byte allowance per record must fit within 4 MiB. Titles, heading arrays, note paths, hashes and source metadata are included in those records. Obviously oversized documents bypass serialization and the queue and are committed alone; a serialization allocation exceeding the remaining bound also cannot enter the queue. Decoding and native work are transient, and these bounds do not cap a large source read or total process RSS. Each flush uses one synchronous native transaction and publishes its source-map entries only after the commit. Only the dedicated reconciliation wrapper may reuse that transaction, since an arbitrary caller could catch errors inside a revision transaction. Other store operations retain their own rollback guards. Residual records flush before retrieval; failed batches roll back, source workers drain, and an incomplete refresh returns no query result. SQLite durability settings and full-corpus ranking/freshness checks retain their existing behavior. In-memory captures keep one complete document commit followed by the existing page-budget check: FTS pending terms are not fully represented by page counts until commit, so batching starts only after spill.

Read-only SQLite access captures the main database and WAL twice and requires matching byte digests and file identity before opening the disposable copy. The first pass streams into private temporary files; the second pass hashes through the same 1 MiB buffer. Source SQLite handles are never opened, source bytes and sidecars are not changed, and a failed capture closes all descriptors and removes the temporary copy. This bounds JavaScript capture buffers independently of index size; it does not claim a bound on SQLite caches or the rest of the process.

## Public surfaces

The CLI does not require a host. The three public sets stay independent:

| Set | What it is |
| --- | --- |
| Six skills | `distill`, `doctor`, `interview`, `search`, `setup`, `write`. Host workflows. `distill` and `setup` are tool-less. |
| Four MCP tools | `write`, `search`, `interview`, `doctor`, from `oms serve mcp`. A subset of the skills. Only `search` is annotated read-only. |
| Seven CLI families | `search`, `interview`, `write`, `setup`, `doctor`, `serve`, and the hidden `hook`. Not the skill list and not the tool list. |

Sealing has no MCP operation. Leaves, discriminators, and removed operations are only in [the CLI map](./cli-map.md); the 0.18 spellings are mapped in [the migration guide](./migration-0.19.md). `setup bridge` manages the repository-to-vault target. `search --link` suggests and `doctor link-check` checks note wikilinks; neither applies them. `setup package update` does not sync hosts. `oms serve mcp` and `oms serve http` do not create a vault engine store by starting.

### MCP namespace boundary

The MCP server id is `oms`. Local tool names are `write`, `search`, `interview`, and `doctor`. Qualifying hosts therefore display `oms_write`, `oms_search`, `oms_interview`, and `oms_doctor` exactly once, never `oms_oms_*`. Raw MCP clients call the local names.

Directly under `src`, the five top-level entries are still assets, cli, kernel, mcp, and vendors. There is no sixth MCP tool. The skill, tool, and command names above are the approved public surface. Retired note, link, and template operations have no compatibility path.

See [conventions](./conventions.md) for vault data and [installation](./install.md) for host setup.

## Explicit maintenance lifecycle

The maintenance controller is an optional owner inside the existing MCP/HTTP process. It is off by default and starts only from an explicit server flag after verified-target, existing-store, runtime and model checks. It reuses the engine SQLite store and revisioned dirty queue. No extra database, daemon, persistent change journal, or automatic host configuration is introduced. Private observed metadata still uses the existing session-owned AxisObservationStore.

Per-document maintenance publishes lexical rows, source evidence and a unique pending embedding revision in one SQLite transaction. Inference holds no writer handle; its eventual commit checks the captured bytes, chunker/model identity, queued revision and current owner. A source edit, deletion/recreation, owner loss or cancellation makes late work stale. This transaction is not atomic with Markdown saves; startup and periodic reconciliation provide convergence, while retrieval retains its source-freshness checks.

Maintenance ownership and the short database writer gate are separate. Each upgraded contender publishes a unique immutable process record before listing competitors. Any other live or unknown process blocks acquisition; concurrent arrivals may both refuse and retry. Dead records have never-reused names, so recovery does not rename a live successor's path. PID reuse conservatively blocks. These are cooperative guarantees within one host and PID namespace, not strong fencing against manual lock tampering or old-version recovery code. A complete private lexical corpus can remain warm across persistent index changes because it independently reconciles admitted Markdown.

A strict full scan is required before pruning absent or excluded indexed paths. Watcher hints are registered before scanning, coalesced during it and bounded by overflow-to-rescan. Watch failures remain visible and trigger complete reconciliation. The owner stops scheduling on scope loss, cancels jobs and retains ownership until active work drains. See [optional maintenance operation](./install.md#optional-automatic-index-maintenance) for prerequisites and limits.
